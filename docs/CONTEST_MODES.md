# 当前所有环节模式与比赛规则

本文按当前选手端代码实现整理所有已落地的环节模式，供赛段配置、联调、主持人控场和比赛规则核对使用。

判定依据主要来自：

- `src/features/quiz/modes.ts`
- `src/features/quiz/types.ts`
- `src/features/quiz/useControlCommands.ts`
- `src/features/quiz/useQuizRuntime.ts`
- `src/features/quiz/hooks/useQuizSubmission.ts`
- `src/features/quiz/challenge.ts`
- `src/features/quiz/ultimateBuzzer.ts`
- `src/features/quiz/oceanGroup.ts`
- `src/features/quiz/status.ts`
- `src/pages/QuizPage.tsx`

## 1. 文档范围

当前选手端真正实现的答题 / 控制模式共 12 个：

| modeId | 环节名称 | 环节类型 | 题目来源 | 主控方式 |
| --- | --- | --- | --- | --- |
| `qa` | 有问必答 | 标准答题 | Fusion 题库表 | 主持人 MQTT 推题 / 收题 |
| `qa-challenge` | 有问必答挑战题 | 挑战题 | Fusion 题库表 | 题主选作答队伍，主持人 MQTT 收题 |
| `qa-20` | 有问必答(20) | 标准答题 | Fusion 题库表 | 主持人 MQTT 推题 / 收题 |
| `qa-30` | 有问必答(30) | 标准答题 | Fusion 题库表 | 主持人 MQTT 推题 / 收题 |
| `qa-50` | 有问必答(50) | 标准答题 | Fusion 题库表 | 主持人 MQTT 推题 / 收题 |

以下记录不是选手端答题模式：

- `赛事海报`：从赛段列表中过滤，只用于等待页海报展示。
- `学校信息`：属于 `meta` 赛段，用于加载队伍 / 选手资料，不映射到 `/quiz?mode=...`。
- `总分排名`：等待页排行榜数据源，不是答题模式。

## 2. 赛段如何映射到模式

### 2.1 模式识别优先级

收到 `<stageId>-start` 后，选手端会先在当前赛事赛段表中找到 `ID=<stageId>` 的赛段，再按以下顺序识别 `mode`：

1. 优先读取赛段原始字段中的模式字段：
   - `模式`
   - `Mode`
   - `mode`
   - `模式ID`
   - `ModeId`
   - `modeId`
   - `答题模式`
   - `答题模式ID`
   - `答题模式Id`
2. 若未配置模式字段，再回退到 `环节名称` 与 `显示名称`。
3. 若仍无法识别：
   - `kind=grab` 默认视为 `ocean-adventure`
   - `kind=standard` 默认视为 `qa`

### 2.2 常见名称别名

当前代码已兼容的典型别名包括：

| 别名 / 名称 | modeId |
| --- | --- |
| `有问必答`、`火眼金睛`、`问答`、`问答赛` | `qa` |
| `有问必答挑战题`、`有问必答挑战` | `qa-challenge` |
| `有问必答(20)`、`火眼金睛（20）` | `qa-20` |
| `有问必答(30)`、`火眼金睛（30）` | `qa-30` |
| `有问必答(50)`、`火眼金睛（50）` | `qa-50` |
| `一站到底`、`1v1` | `last-stand` |
| `一站到底(分组)`、`一站到底（初中组）`、`一站到底（中职组）`、`一站到底（高中组）` | `last-stand-group` |
| `争分夺秒`、`速答`、`冲刺` | `speed-run` |
| `题海遨游`、`题海` | `ocean-adventure` |
| `终极挑战`、`同分加题`、`同分加題` | `ultimate-challenge` |

注意：`火眼金睛.*` 的模糊匹配会归到 `qa`，如果需要明确进入 `qa-20` / `qa-30` / `qa-50`，建议直接配置模式字段。

### 2.3 赛段 ID 与启动指令

主持人发送 `<stageId>-start` 时，`stageId` 来自 Fusion 赛段记录的 `ID` 字段。

- 若 `ID` 缺失，前端回退使用赛段顺序号。
- 因此 `1-start`、`2-start` 具体对应哪个环节，取决于当前赛事的 Fusion 配置，不是仓库里的固定常量。

统一启动格式：

```text
主题: cmd
payload: <stageId>-start
```

示例：若当前赛段 `ID=4` 是 `争分夺秒`，则发送 `4-start`。

### 2.4 启动后的通用控制

| payload | 作用 |
| --- | --- |
| `refresh` | 重置选手端并回到 `/waiting` |
| `home` | 回到等待页 |
| `rank` | 打开等待页排行榜视图 |
| `race-N` | 切换到第 N 个赛事，N 从 1 开始 |
| `<stageId>-start` | 启动指定赛段 |
| 纯数字，例如 `3` | 切到第 3 题，同时打开题目闸门 |
| `question 3` / `q3` | 旧格式切题，仍兼容，但建议统一直接发数字 |

## 4. 主持人控制矩阵

除公共命令 `refresh`、`home`、`rank`、`race-N`、`<stageId>-start` 外，各模式常用控制如下：

| 模式 | 数字切题 | `submit` | `answer` | `retract` | `pool-start` | `quiz/control start_buzzing` | `quiz/result` | `stage-*` |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `qa` / `qa-20` / `qa-30` / `qa-50` | 是 | 是 | 是 | 否 | 否 | 否 | 否 | 否 |
| `qa-challenge` | 是 | 是 | 是 | 否 | 否 | 否 | 否 | 否 |
| `last-stand` | 是 | 是 | 是 | 是 | 否 | 否 | 否 | 否 |
| `last-stand-group` | 是 | 是 | 是 | 是 | 否 | 否 | 否 | 否 |
| `speed-run` | 是，首次数字开闸 | 否 | 否 | 否 | 否 | 否 | 否 | 否 |
| `ocean-adventure` | 否 | 否 | 否 | 否 | 是 | 否 | 否 | 否 |
| `ultimate-challenge` | 是 | 是 | 是 | 否 | 否 | 是 | 是 | 否 |
| `buzzer-sprint` | 是 | 是 | 是 | 否 | 否 | 是 | 是 | 否 |
| `ultimate-pk` | 否 | 否 | 否 | 否 | 否 | 否 | 否 | 是 |

说明：

- `cmd answer` 会让当前题进入答案揭晓态，不等同于切换页面。
- `cmd retract` 只对一站到底类模式有业务意义，用于恢复上一题扣血。
- 数字切题会清掉当前题的提交遮罩、答案揭晓态；在抢答模式中还会重置抢答锁定。
- `ultimate-pk` 监听 `cmd` 的 `stage-1`、`stage-2`、`stage-3`、`stage-4`、`stage-5`，不走普通题号切题。

## 5. 题型与作答规则

标准题库模式支持以下题型：

| 归一题型 | 典型别名 | 选手端提交要求 |
| --- | --- | --- |
| `single` | `single`、`single-choice`、`单选`、`单选题` | 必须选择 1 个选项 |
| `multiple` | `multiple`、`multiple-choice`、`多选`、`多选题` | 必须至少选择 1 个选项 |
| `indeterminate` | `indeterminate`、`不定项选择` | 必须至少选择 1 个选项 |
| `boolean` | `boolean`、`true-false`、`判断`、`判断题` | 必须选择 1 个选项 |
| `fill` | `fill`、`fill-in`、`text`、`填空`、`填空题` | 使用画板上传作答；主持人收题时允许空画板占位 |
| `wordbank` | `wordbank`、`word-bank-fill`、`选词填空` | 必须完成所有空位 |
| `point-select` | `point-select`、`tap-select`、`点选`、`选字组词` | 必须至少选择 1 个词元 |
| `matching` | `matching`、`match`、`连线题`、`配对题` | 必须完成全部左侧项连线；无左侧配置时至少完成一条 |

判题规则：

- 单选 / 判断：提交值与标准答案完全相等。
- 多选 / 不定项：提交集合与标准答案集合排序后完全一致。
- 选词填空：按空位顺序逐项完全相等。
- 点选 / 选字组词：去掉空白后拼接比较。
- 连线题：提交为 `左ID:右ID` 关系数组，按题目配置排序后回写。
- 题海题：按 `correctAnswerIds` 集合比较。

## 6. 各模式详细比赛规则

### 6.1 `qa`：有问必答

#### 启动与题目

- 启动：`cmd` -> `<有问必答赛段ID>-start`
- 题目来源：当前赛段 `题库表ID` 指向的 Fusion 题库表。
- 进入赛段时会预加载整份题库，但题目闸门默认关闭。
- 主持人发送数字题号后，页面显示对应题目。

#### 比赛流程

1. 主持人启动赛段。
2. 主持人发送题号，例如 `1`。
3. 选手在当前题上本地选择答案。
4. 主持人发送 `submit`，前端正式提交并锁定当前答案。
5. 如需公布答案，主持人发送 `answer`。
6. 主持人发送下一题题号，进入下一题。

#### 计分与回写

- 提交时会把选手答案写入题库表当前题记录，字段名默认是当前选手 `userId`。
- 同时会向分数表写入当前题判题结果：
  - `answer`: 正确为 `1`，错误为 `0`；画板填空题写 `填空`
  - `light`: 正确为 `1`，错误为 `0`
- 题号字段优先取题库题目里的 `number`、`Number`、`题号`、`序号`、`题目编号`，否则用当前题序号。

#### 规则边界

- 无全局倒计时。
- 无血量。
- 不自动进入下一题。
- `qa-20` / `qa-30` / `qa-50` 不是这个模式的自动计分倍率，详见后文。

### 6.2 `qa-20` / `qa-30` / `qa-50`：有问必答分值变体

#### 启动

- `qa-20`：`cmd` -> `<有问必答(20)赛段ID>-start`
- `qa-30`：`cmd` -> `<有问必答(30)赛段ID>-start`
- `qa-50`：`cmd` -> `<有问必答(50)赛段ID>-start`

#### 比赛规则

这三个模式当前在前端运行时上与 `qa` 相同：

- 都从 Fusion 题库表加载标准题。
- 都需要主持人数字切题。
- 都需要主持人发送 `submit` 才正式收题。
- 都支持 `answer` 答案揭晓。
- 都不会自动推进下一题。
- 都不会自动启用倒计时或血量。

#### 当前实现差异

差异只体现在：

- `modeId`
- 模式名称
- URL 参数 `/quiz?mode=qa-20` / `/quiz?mode=qa-30` / `/quiz?mode=qa-50`
- 外部赛段配置和分数表列名可按不同分值自行区分

前端当前不会因为 `20` / `30` / `50` 自动给分或自动改判题结果。

### 6.3 `qa-challenge`：有问必答挑战题

#### 启动与配置

- 启动：`cmd` -> `<挑战题赛段ID>-start`
- 模式别名：`qa-challenge`、`有问必答挑战题`、`有问必答挑战`
- 题目来源：Fusion 题库表。
- 当前挑战题配置要求：题库中必须正好有 9 道配置了 `owner` 的题目。

题库题目扩展字段：

| 字段 | 说明 |
| --- | --- |
| `owner` | 当前题的题主队伍 / 选手 ID |
| `challengeTarget` | 已锁定的作答队伍 / 选手 ID |

赛段扩展字段：

| 字段 | 说明 |
| --- | --- |
| `challengeScoreField` / `ChallengeScoreField` / `challenge_score_field` / `挑战分数字段` / `挑战积分字段` | 挑战积分写入分数表的字段名，默认 `challengeScore` |

#### 挑战选人规则

1. 每道题由 `owner` 对应的设备选择作答队伍。
2. 题主可以选择本队自己作答。
3. 题主也可以选择其他队伍作答。
4. 已作为 `challengeTarget` 被锁定过的队伍，不能再次被其他题选择。
5. 选择确认后不可在 UI 中修改。
6. 选择后前端会：
   - 向 `cmd` 发布 `challenge:<owner>:<challengeTarget>`
   - 本地更新当前题 `challengeTarget`
   - 将 `challengeTarget` 回写到题库表当前题记录

#### 作答资格

- 只有当前题 `challengeTarget` 对应的设备可以作答。
- 题主未选择作答队伍前，当前题不会开放作答。
- 非作答队伍可以看到题目和挑战状态，但不能提交答案。

#### 提交与公布

挑战题仍使用主持人收题节奏：

1. 主持人数字切题。
2. 题主选择作答队伍。
3. 被选队伍作答。
4. 主持人发送 `submit` 收题。
5. 主持人可发送 `answer` 公布答案。
6. 主持人发送下一题题号进入下一题。

#### 挑战积分规则

当前前端已落地的挑战积分规则如下：

| 场景 | 正误 | 获得挑战积分 |
| --- | --- | --- |
| 题主选择本队作答 | 答对 | 题主 +20 |
| 题主选择本队作答 | 答错 | 无人加分 |
| 题主挑战其他队伍 | 被挑战队答对 | 被挑战队 +20 |
| 题主挑战其他队伍 | 被挑战队答错 | 题主 +20 |

积分通过同步队列写入当前赛段 `分数表ID`，字段默认为 `challengeScore`，每次增量为 `20`。

#### 配置校验

前端会校验：

- 配置了 `owner` 的挑战题必须正好 9 道。
- `owner` 不能重复。
- 已配置的 `challengeTarget` 不能重复。

校验失败时会展示配置错误，不影响本文档描述的普通 `qa` 模式。

### 6.4 `last-stand`：一站到底

#### 启动与题目

- 启动：`cmd` -> `<一站到底赛段ID>-start`
- 题目来源：Fusion 题库表。
- 流程与 `qa` 类似，由主持人数字切题和 `submit` 收题。

#### 血量规则

- 每名选手初始 3 点血量。
- 答错扣 1 点血。
- 答对不扣血。
- 血量归零后进入淘汰态，不再允许继续作答。

#### 分数表状态同步

提交后前端会把血量同步到分数表状态字段。

状态字段按以下候选名查找：

- `状态`
- `血量`
- `生命值`
- `status`
- `Status`

如果分数表中没有上述字段，默认按 `状态` 字段写入。

#### 回退规则

主持人发送 `retract` 时：

- 仅当上一题确实发生过扣血，才会尝试恢复。
- 恢复目标是上一题扣血前的血量。
- 前端最多重试 3 次写回分数表状态。
- 若没有上一题扣血记录，会提示无需回退。

### 6.5 `last-stand-group`：一站到底（分组）

#### 启动与题目

- 启动：`cmd` -> `<一站到底分组赛段ID>-start`
- 题目来源：Fusion 题库表。
- 主持人数字切题，主持人 `submit` 收题。

#### 血量规则

- 每个设备 / 队伍初始 1 点血量。
- 答错扣 1 点。
- 答错即血量归零并淘汰。
- 淘汰后不再允许继续作答。

#### 分组状态规则

分组一站到底除了前端血量外，还会按赛段名写入分组状态标识：

| 赛段名 | 存活状态值 |
| --- | --- |
| `一站到底(高中组)` / `一站到底（高中组）` | `1` |
| `一站到底(中职组)` / `一站到底（中职组）` | `2` |
| `一站到底(初中组)` / `一站到底（初中组）` | `3` |
| 淘汰 | `0` |

如果赛段名无法识别出初中 / 中职 / 高中组，存活状态无法可靠同步，前端会跳过对应状态写入。

#### 回退规则

`retract` 与普通一站到底一致，但分组模式恢复的是分组状态：

- 恢复后血量大于 0，则写回对应组别存活值。
- 恢复后血量为 0，则写 `0`。

### 6.6 `speed-run`：争分夺秒

#### 启动与开闸

- 启动：`cmd` -> `<争分夺秒赛段ID>-start`
- 进入赛段后会一次性从当前赛段 `题库表ID` 拉取整份题包。
- 题目加载完成后显示等待页，不立即开始。
- 主持人发送首次数字题号后打开题目闸门，倒计时开始。

#### 计时规则

- 使用全局倒计时。
- 倒计时秒数读取当前赛段原始字段 `URL`。
- 只有当 `URL` 是纯数字且大于 0 时才生效。
- 未填、非数字或无效时默认 120 秒。
- 倒计时从题目闸门打开后启动，不从赛段刚进入时启动。

#### 作答与推进

1. 选手在当前题作答。
2. 选手手动点击提交。
3. 提交后立即进入下一题。
4. 最后一题提交后进入结果页。

#### 计分与回写

每题提交后会同步：

- 题库表：写入当前选手答案。
- 分数表：写入判题结果。
- `time` 字段：写入提交时剩余秒数。
- `light` 字段：正确为 `1`，错误为 `0`。

倒计时耗尽时：

- 停止作答。
- 进入超时结果页。
- 若分数表与选手分数记录存在，会额外同步 `time: "0"`。

#### 结果页

结果页展示：

- 总题数
- 已答题数
- 正确数
- 错误数
- 未答题数
- 剩余时间

结束原因：

- `complete`：全部题目作答完成。
- `timer`：倒计时耗尽。

### 6.7 `ocean-adventure`：题海遨游

#### 启动与配置

- 启动：`cmd` -> `<题海遨游赛段ID>-start`
- 进入赛段后会请求题海配置接口 `/config`。
- 配置必须返回：
  - `questionCount`
  - `timeLimitSeconds` 或 `roundTimeLimitSeconds`
  - `mode`
  - 可选 `loadedPresetName`

`mode` 只接受：

- `solo` / `个人` / `个人模式`
- `group` / `团队` / `团队模式`

配置格式不正确时，前端会拦截开始指令并提示配置异常。

#### 个人 / 团队规则

当前题海模式不是由选手自由切换个人 / 团队，而是由题海配置接口决定：

- `mode=solo`：当前环节为个人模式，主持人开始后直接抢题，不需要选红蓝队。
- `mode=group`：当前环节为团队模式，选手必须先选择 `红队` 或 `蓝队`。
- 团队模式下，第一次成功抢题后队伍选择锁定。
- 回到等待态且尚未抢到题时，锁定会解除。

#### 开始抢题

主持人发送：

```text
主题: cmd
payload: pool-start
```

前端处理条件：

- 当前赛段必须是 `kind=grab`。
- 当前仍处于等待开始状态。
- 题海配置已成功加载。
- 团队模式下必须已选择红 / 蓝队。

满足条件后：

- 个人模式调用抢题接口时不传 `groupId`。
- 团队模式调用抢题接口时传 `groupId=red` 或 `groupId=blue`。

#### 作答与推进

1. `pool-start` 抢到第一题。
2. 选手作答并手动提交。
3. 提交成功后，如果未被淘汰，前端自动请求下一题。
4. 如果题库已空，进入题库耗尽结束态。

#### 计时与血量

- 初始血量：2。
- 答错扣 1 点血。
- 血量归零后结束，原因记为 `hp`。
- 全局倒计时来自题海配置 `timeLimitSeconds`。
- 倒计时结束后结束，原因记为 `timer`。
- 题库耗尽后结束，原因记为 `empty`。

#### 成绩与排行

题海提交通过题海 API 完成，响应可携带：

- `result`
- `correctAnswer`
- `score`
- `stats`

结束页会额外请求：

```text
GET /user/<userId>/answers
```

展示：

- 总题数
- 正确数
- 错误数
- 得分
- 正确率
- 最近答题时间

团队模式下，抢题和提交会带 `groupId`，题海服务端负责个人 / 分组成绩归集。

### 6.8 `ultimate-challenge`：终极挑战

#### 启动与题目

- 启动：`cmd` -> `<终极挑战赛段ID>-start`
- 题目来源：Fusion 题库表。
- 主持人数字切题后，当前题进入 `buzz` 阶段。

#### 阶段规则

当前实现里的主要阶段：

| 阶段 | 含义 |
| --- | --- |
| `waiting` | 等待主持人推题 |
| `buzz` | 已有题目，等待主持人开启抢答 |
| `locked` | 其他队伍 / 选手获得答题权，本设备锁定 |
| `answer` | 本设备获得答题权，可以作答 |
| `submitted` | 本题已提交，等待主持人后续指令 |

#### 抢答链路

1. 主持人数字切题。
2. 主持人向 `quiz/control` 发送 `start_buzzing`。
3. 页面在 `buzz` 阶段开放抢答按钮。
4. 选手点击抢答，前端向 `quiz/buzz_in` 发送：

```json
{"player_id":"<user.id>"}
```

5. 主持人端 / 中控向 `quiz/result` 广播抢答结果：

```json
{"winnerId":"<user.id>"}
```

6. 如果 `winnerId` 等于当前选手 `user.id`，当前设备进入 `answer`。
7. 如果 `winnerId` 是其他选手，当前设备进入 `locked`。

#### 作答与收题

- 只有 `answer` 阶段可以作答。
- 主持人发送 `submit` 后，前端正式提交当前答案。
- 提交后进入 `submitted` 阶段。
- 主持人发送 `answer` 时进入答案揭晓态。
- 主持人发送新题号时重置抢答状态，进入下一题。

#### 规则边界

- 当前模式不使用血量。
- 抢答身份是当前登录选手 `user.id`。
- `quiz/result` 必须是 JSON，且包含 `winnerId` / `winner_id` / `winnerID`。
- 非 `buzz` 阶段收到 `start_buzzing` 不会生效。

### 6.9 `buzzer-sprint`：抢答冲刺

#### 启动与入场

- 启动：`cmd` -> `<抢答冲刺赛段ID>-start`
- 题目来源：Fusion 题库表。
- 进入赛段前必须选择当前设备代表：
  - `红队`
  - `蓝队`

收到赛段启动指令后，路由会带 `entry` 参数，触发入场选队弹窗。选择成功后保存：

- `sprintTeamId=red` 或 `blue`
- 当前赛段 `stageId`
- 队伍锁定状态

#### 红蓝队规则

- 抢答身份不是当前选手 `user.id`，而是当前设备锁定的 `red` / `blue`。
- 若未选择队伍，点击抢答会提示先确认当前代表队伍。
- 当前设备可在等待 / 未抢答阶段重新选择队伍。
- 切换到其他赛段时会清空抢答冲刺队伍选择。

#### 抢答链路

1. 主持人数字切题。
2. 主持人向 `quiz/control` 发送 `start_buzzing`。
3. 选手点击抢答，前端向 `quiz/buzz_in` 发送：

```json
{"player_id":"red"}
```

或：

```json
{"player_id":"blue"}
```

4. 主持人端 / 中控向 `quiz/result` 广播：

```json
{"winnerId":"red"}
```

或：

```json
{"winnerId":"blue"}
```

5. 若 `winnerId` 等于当前设备锁定队伍，进入 `answer`。
6. 若 `winnerId` 是另一队，进入 `locked`。

#### 提交与回写

- 只有获得答题权的队伍可以作答。
- 主持人发送 `submit` 后正式提交。
- 回写题库表时，答案字段优先使用 `red` / `blue`，而不是当前用户 ID。
- 分数表记录会按 `team_id` 查找红 / 蓝队对应记录。
- 主持人发送 `answer` 可公布答案。
- 新题号会重置抢答锁定。

### 6.10 `ultimate-pk`：终极 PK

#### 模式定位

`ultimate-pk` 不走常规答题链路。页面主体是“发言权切换面板”，用于正反方发言权切换。

#### 初始状态

- 默认选中 `正方`。
- 默认处于锁定状态。
- 主持人未解锁前，选手不能发送切换。

#### 主持人控制

`ultimate-pk` 额外监听 `cmd` 主题。

支持两种 payload：

- 纯文本
- JSON，并从 `command`、`type`、`action` 中读取命令字

命令规则：

| payload | 作用 |
| --- | --- |
| `stage-3` | 解锁切换 |
| `stage-1` | 锁定切换 |
| `stage-2` | 锁定切换 |
| `stage-4` | 锁定切换 |
| `stage-5` | 锁定切换 |

#### 选手端上行消息

当主持人解锁后，选手点击“切换发言”会向 `cmd` 发布：

| 当前选择 | 发布 payload |
| --- | --- |
| `正方` | `switch-blue` |
| `反方` | `switch-red` |

附加规则：

- 发布使用 `qos: 1`。
- 客户端本地有 1 秒节流。
- 主持人重新锁定时，会清除节流与发送中状态。

## 7. 模式所需配置清单

### 7.1 标准题库模式

适用：

- `qa`
- `qa-challenge`
- `qa-20`
- `qa-30`
- `qa-50`
- `last-stand`
- `last-stand-group`
- `speed-run`
- `ultimate-challenge`
- `buzzer-sprint`

赛段配置建议：

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| `ID` | 必需 | 用于 `<stageId>-start` |
| `环节名称` | 必需 | 用于识别赛段类型 |
| `显示名称` | 可选 | UI 展示名 |
| `模式` / `mode` 等模式字段 | 强烈建议 | 避免靠名称模糊匹配 |
| `题库表ID` | 必需 | 标准题来源 |
| `分数表ID` | 需要计分时必需 | 判题、血量、挑战积分写入 |
| `通用表ID` | 需要队伍名 / 挑战选队 / 抢答显示时建议 | 队伍资料来源 |
| `URL` | `speed-run` 可用 | 纯数字时作为倒计时秒数 |

### 7.2 题海模式

适用：

- `ocean-adventure`

赛段配置：

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| `ID` | 必需 | 用于 `<stageId>-start` |
| `环节名称` | 必需 | 建议 `题海遨游` |
| `模式` / `mode` | 可选 | 未配也会因 `kind=grab` 进入题海模式 |

题海配置接口 `/config` 必须返回：

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| `questionCount` | 必需 | 当前题包题量 |
| `timeLimitSeconds` / `roundTimeLimitSeconds` | 必需 | 全局倒计时秒数，必须大于 0 |
| `mode` | 必需 | `solo` 或 `group` |
| `loadedPresetName` | 可选 | 当前题包名称 |

### 7.3 终极 PK

适用：

- `ultimate-pk`

该模式不依赖题库表和分数表，但仍建议配置：

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| `ID` | 必需 | 用于 `<stageId>-start` |
| `环节名称` / `模式` | 必需 | 用于识别 `ultimate-pk` |

## 8. 当前实现边界

- `qa-20` / `qa-30` / `qa-50` 不会自动按 20 / 30 / 50 加分。
- `ultimate-challenge` 和 `buzzer-sprint` 的 `supportsTimer=true` 是能力标记，当前比赛主计时仍由主持人 / 外部流程控制，前端没有像 `speed-run` 那样自动倒计时结束。
- `ocean-adventure` 的个人 / 团队模式以题海配置接口为准，不再由选手自由选择模式。
- `last-stand-group` 的分组状态依赖赛段名能识别初中 / 中职 / 高中组。
- `qa-challenge` 的挑战积分是额外增量写入，不替代普通题目判题回写。
- `ultimate-pk` 是控制面板，不是答题模式。
