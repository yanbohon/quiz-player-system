# Quiz 人工冒烟脚本

## 目标

- 用 20 到 40 分钟验证选手端最关键的真实链路仍然可用。
- 覆盖自动化测试不擅长的部分：
  - MQTT 指令联动
  - 抢答与锁定流程
  - 画板与连线的视觉交互
  - 队列失败后的页面反馈

## 适用时机

- `src/app/quiz/page.tsx` 或 `src/features/quiz` 大改后
- 发布前
- 接入新赛制、新题型、新 MQTT 指令后

## 测试角色

| 角色 | 用途 | 最低要求 |
| --- | --- | --- |
| 主持人端 / 指令发送端 | 向 MQTT 发命令、控制抢答和切换环节 | 能向 `cmd`、`quiz/control`、`quiz/result` 发消息 |
| 选手端 A | 主测页面行为 | 登录成功，能进入 `/waiting` 和 `/quiz` |
| 选手端 B | 验证抢答失败、对手作答、团队模式 | 至少一个额外账号 |

## 前置条件

1. 本地基线已通过：
   - `npm run type-check -- --pretty false`
   - `npm test`
2. MQTT 服务可连接，默认主题如下：
   - 命令主题：`cmd`
   - 控制主题：`quiz/control`
   - 抢答结果主题：`quiz/result`
   - 抢答上报主题：`quiz/buzz_in`
3. 测试赛事已准备好至少这些赛段：
   - `speed-run`
   - `ocean-adventure`
   - `last-stand` 或 `last-stand-group`
   - `ultimate-challenge`
   - `buzzer-sprint`
   - `ultimate-pk`
4. 选手端起始页为 `/waiting`。
5. 浏览器 DevTools 已打开：
   - Console
   - Network
6. 如本地残留状态不可信，先发送一次 `refresh` 指令重置。

## 记录方式

建议执行时维护一张结果表：

| 用例 ID | 结果 | 备注 |
| --- | --- | --- |
| G-01 | Pass / Fail / Blocked | 失败时记录实际文案、控制台报错、MQTT 消息 |

## MQTT 指令速查

| 场景 | 主题 | 示例 payload |
| --- | --- | --- |
| 重置选手端 | `cmd` | `refresh` |
| 返回等待页 | `cmd` | `home` |
| 打开排行榜 | `cmd` | `rank` |
| 切换赛事 | `cmd` | `race-2` |
| 启动赛段 | `cmd` | `1-start` |
| 切题 | `cmd` | `3` |
| 题海开始取题 | `cmd` | `pool-start` |
| 开启抢答 | `quiz/control` | `start_buzzing` 或 `{"action":"start_buzzing"}` |
| 抢答结果 | `quiz/result` | `{"winnerId":"user-1"}` |
| 终极 PK 解锁切换 | `cmd` | `stage-3` |
| 终极 PK 锁定切换 | `cmd` | `stage-1` / `stage-2` / `stage-4` / `stage-5` |

## 一、公共命令冒烟

### G-01 `refresh` 重置

前置：
- 选手端位于任意页面

步骤：
1. 向 `cmd` 发布 `refresh`

预期：
- 页面跳回 `/waiting`
- 出现提示：`选手端已重置`
- 当前题目、临时状态、等待票据视图被清空
- Console 无未捕获异常

### G-02 `home` 返回等待页

前置：
- 选手端已在 `/quiz`

步骤：
1. 向 `cmd` 发布 `home`

预期：
- 页面跳回 `/waiting`
- 不出现报错提示

### G-03 `rank` 排行榜

前置：
- 已加载赛事

步骤：
1. 向 `cmd` 发布 `rank`

预期：
- 页面回到 `/waiting`
- 排行榜数据加载成功

异常分支：
- 若当前赛事没有排行榜赛段，应只提示 `未加载赛事`
- 不应出现白屏

### G-04 `race-*` 切换赛事

步骤：
1. 向 `cmd` 发布 `race-2`

预期：
- 出现提示：`已切换到赛事 2`
- 后续 `rank`、`1-start` 等操作基于新赛事生效

### G-05 `*-start` 启动赛段

步骤：
1. 向 `cmd` 发布 `1-start`

预期：
- 页面跳转到 `/quiz?mode=...`
- `mode` 与赛段实际配置一致
- 页面标题、赛制名称、内容区域不串线

### G-06 数字切题

前置：
- 当前赛段支持主持人切题

步骤：
1. 向 `cmd` 发布 `3`

预期：
- 页面切到第 3 题
- 进度卡题号同步为第 3 题
- 已答题不会被错误重置

## 二、`speed-run`

### SR-01 赛段等待页

步骤：
1. 进入 `speed-run` 赛段

预期：
- 显示 `题目加载完成`
- 显示 `请做好准备 比赛即将开始`
- 显示已准备题数

### SR-02 开始答题与切题

步骤：
1. 发送 `question 1`
2. 回答当前题并点击提交

预期：
- 进入第 1 题
- 进度卡显示 `1 / 总题数`
- 倒计时开始工作
- 提交后自动进入下一题

### SR-03 完成结局

步骤：
1. 正常作答直到全部题目完成

预期：
- 结果页显示完成态文案
- 正确题数、总题数、耗时展示正确

### SR-04 超时结局

步骤：
1. 进入赛段后等待倒计时耗尽

预期：
- 结果页显示超时态文案
- 不再允许继续答题

## 三、`ocean-adventure`

### OA-01 等待页模式选择

步骤：
1. 进入 `ocean-adventure` 赛段

预期：
- 显示 `题库准备就绪`
- 可选择 `个人模式` 或 `团队模式`
- 团队模式下可选择 `红队` / `蓝队`

### OA-02 未选模式时开始取题

步骤：
1. 不做任何模式选择
2. 向 `cmd` 发布 `pool-start`

预期：
- 提示：`请先选择个人模式或团队模式`
- 不下发题目

### OA-03 团队模式未选队伍

步骤：
1. 选择 `团队模式`
2. 不选 `红队` / `蓝队`
3. 向 `cmd` 发布 `pool-start`

预期：
- 提示：`请先选择红队或蓝队`
- 不下发题目

### OA-04 个人模式开始取题

步骤：
1. 选择 `个人模式`
2. 向 `cmd` 发布 `pool-start`

预期：
- 模式锁定
- 下发题目
- 提交按钮文案为 `提交并抢下一题`

### OA-05 团队模式开始取题

步骤：
1. 选择 `团队模式`
2. 选择 `红队` 或 `蓝队`
3. 向 `cmd` 发布 `pool-start`

预期：
- 选中的队伍被锁定
- 下发题目
- 进度卡或状态区显示当前队伍标签

### OA-06 提交与血量

步骤：
1. 正确作答一题
2. 错误作答一题

预期：
- 正确时能自动抢下一题
- 错误时血量减少
- 当血量归零时进入结束结果页

### OA-07 三种结束路径

至少验证下面三条中的每一条各一次：

1. 血量耗尽
2. 倒计时结束
3. 题库耗尽

预期：
- 三种结果标题与副文案各自正确

### OA-08 成绩获取失败后重试

步骤：
1. 让成绩接口返回错误
2. 在结果页点击 `重新获取成绩`

预期：
- 先出现错误态
- 点击后重新发起请求
- 成功后恢复正常成绩展示

## 四、`last-stand` / `last-stand-group`

### LS-01 错误扣血

步骤：
1. 进入 `last-stand`
2. 故意答错一题

预期：
- 血量减少
- 页面不应切到错误赛制 UI

### LS-02 淘汰态

步骤：
1. 连续答错直到血量耗尽

预期：
- 页面显示 `您已淘汰`
- 显示 `血量已耗尽，无法继续作答。`
- 不再允许继续答题

### LSG-01 分组状态写入

前置：
- 进入 `last-stand-group`
- 明确当前是初中组 / 中职组 / 高中组

步骤：
1. 触发一轮需要写状态的分组流程
2. 到后台表中核对对应状态字段

预期：
- 初中组写入 `3`
- 中职组写入 `2`
- 高中组写入 `1`
- 半角 / 全角括号赛段名都能正确映射

## 五、`ultimate-challenge`

### UC-01 等待状态

前置：
- 当前赛段无题目，尚未进入抢答

预期：
- 页面显示 `等待主持人推送题目`

### UC-02 抢答开启

步骤：
1. 主持人推题进入 `buzz` 阶段
2. 向 `quiz/control` 发布 `start_buzzing`

预期：
- `抢答` 按钮变为可点击
- 进度卡状态显示 `等待抢答`

### UC-03 抢答成功

步骤：
1. 选手 A 点击 `抢答`
2. 向 `quiz/result` 发布 `{"winnerId":"<选手A的 user.id>"}`

预期：
- 提示 `抢答成功，开始作答`
- 进入本队作答阶段
- 抢答按钮失效

### UC-04 抢答失败

步骤：
1. 选手 A 点击 `抢答`
2. 向 `quiz/result` 发布 `{"winnerId":"<其他选手 id>"}`

预期：
- 提示 `本题由其他队伍抢答成功`
- 页面进入锁定态或等待对手态
- 若进入锁定态，应显示 `未抢到答题权`

### UC-05 非作答阶段的提交结果遮罩

步骤：
1. 在非 `answer` 阶段让页面进入命令提交锁定态

预期：
- 显示 `提交成功`
- 显示 `请等待大屏公示`

### UC-06 抢答异常

可选验证：

1. MQTT 未连接时点击抢答
2. 主持人尚未开启抢答时点击抢答

预期：
- 前者提示 `尚未连接抢答服务，请稍后重试` 或 `抢答服务暂时不可用，请稍后再试`
- 后者提示 `主持人尚未开启抢答`

## 六、`buzzer-sprint`

### BS-01 入场选队

步骤：
1. 启动 `buzzer-sprint` 对应赛段

预期：
- 进入答题页前先弹出队伍选择框
- 可选择 `红队` 或 `蓝队`
- 若关闭弹窗或不选队伍，不应进入赛段，并提示 `请先确认当前代表队伍`

### BS-02 同赛段复用锁定队伍

前置：
- 已在 `buzzer-sprint` 里选择过 `红队` 或 `蓝队`

步骤：
1. 再次启动同一个 `stageId` 的 `buzzer-sprint`

预期：
- 不再重复弹出队伍选择框
- 页面继续沿用上次锁定的队伍身份

### BS-03 抢答成功

前置：
- 已锁定当前设备代表 `红队` 或 `蓝队`

步骤：
1. 主持人推题进入 `buzz` 阶段
2. 向 `quiz/control` 发布 `start_buzzing`
3. 选手点击 `抢答`
4. 向 `quiz/result` 发布 `{"winnerId":"red"}` 或 `{"winnerId":"blue"}`，其中值与当前设备锁定队伍一致

预期：
- 提示 `抢答成功，开始作答`
- 进入本队作答阶段
- 抢答按钮失效

### BS-04 抢答失败

前置：
- 已锁定当前设备代表 `红队` 或 `蓝队`

步骤：
1. 主持人推题进入 `buzz` 阶段
2. 向 `quiz/control` 发布 `start_buzzing`
3. 选手点击 `抢答`
4. 向 `quiz/result` 发布另一个队伍的 `winnerId`

预期：
- 提示 `本题由其他队伍抢答成功`
- 页面进入锁定态或等待对手态
- 若进入锁定态，应显示 `未抢到答题权`

## 七、`ultimate-pk`

### UPK-01 初始锁定态

步骤：
1. 进入 `ultimate-pk`

预期：
- 默认选中 `正方`
- 状态文案为 `等待主持人允许切换`
- `切换发言` 按钮禁用

### UPK-02 主持人解锁

步骤：
1. 向 `cmd` 发布 `stage-3`

预期：
- 状态文案变为 `当前可切换发言队伍`
- `切换发言` 按钮可点击

### UPK-03 发言队伍切换

步骤：
1. 选择 `正方` 或 `反方`
2. 点击 `切换发言`

预期：
- 成功提示：`切换指令已发送`
- 1 秒内再次点击会提示 `切换冷却中，请稍候`
- 若选择 `正方`，实际发送 payload 为 `switch-blue`
- 若选择 `反方`，实际发送 payload 为 `switch-red`

### UPK-04 主持人重新锁定

步骤：
1. 向 `cmd` 发布 `stage-1`
2. 再分别验证 `stage-2`、`stage-4`、`stage-5`

预期：
- 页面重新进入锁定态
- 冷却中状态被清空

### UPK-05 MQTT 异常

可选验证：

1. 断开 MQTT 后点击 `切换发言`

预期：
- 提示 `尚未连接实时服务，请稍后重试` 或 `实时服务暂不可用，请稍后再试`

## 八、同步队列与弱网退化

### Q-01 提交失败进入队列

步骤：
1. 让提交接口或网络临时失败
2. 在任意可提交赛段提交一题

预期：
- 顶部 `成绩上传队列` 的待处理或失败计数增加
- 可展开看到失败任务详情

### Q-02 失败任务重试

步骤：
1. 恢复网络
2. 点击 `重试`

预期：
- 失败计数下降或归零
- 无重复提交、无页面卡死

## 九、题型专项人工检查

### T-01 连线题几何

步骤：
1. 进入连线题
2. 完成多组连线
3. 触发重分配与清空

预期：
- 连线起止点位置正确
- 不出现明显错位、裁切、残影

### T-02 画板题预览

步骤：
1. 打开画板
2. 生成预览并提交

预期：
- 未作画时显示 `打开画板`
- 有预览后显示预览图
- 提交成功态与禁用态正确

### T-03 移动端触摸热区

步骤：
1. 在移动端或模拟触屏环境测试单选、多选、词库填空、点选题

预期：
- 点击热区准确
- 不需要极高精度才能点中

## 阻断条件

出现以下任一情况，应判定本轮冒烟失败并阻止发布：

- 不能从 `/waiting` 正常进入任一目标赛段
- MQTT 指令已发送但页面完全无响应
- 提交后页面白屏、卡死、无限 loading
- 结果页标题、分数、血量、赛制状态明显串线
- 淘汰态、抢答态、终极 PK 锁定态出现错误页面
- 同步队列失败后无法重试或重试导致重复提交
